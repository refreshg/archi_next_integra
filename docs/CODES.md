# შედეგის კოდები — რა რას ნიშნავს და სად წერია

ყოველი გაშვება მთავრდება **ზუსტად ერთი კოდით**. კოდს წერს `docs/bp/block.php`-ის
ფუნქცია `$finish()`, და ის ოთხ ადგილას ჩანს.

## სად ჩანს შედეგი

| ადგილი | რა წერია | სად ნახავ |
|---|---|---|
| **`Logstat`** (BP ცვლადი) | მხოლოდ კოდი, მაგ. `REJECTED_SAME` | გარიგების ბარათი → ბიზნეს პროცესი |
| **`Send_log`** (BP ცვლადი) | სრული ანგარიში: დრო, ბინა, HTTP კოდები, ხანგრძლივობა | იქვე |
| **BP-ს ჟურნალი** | 2–4 ხაზი, ადამიანური ენით | გარიგება → ბიზნეს პროცესი → ჟურნალი |

### `UPDATED`
სტატუსი შეიცვალა. ეს არის ნორმალური, სასურველი შედეგი.

- **Next-ში:** სტატუსი ახალია, ისტორიას დაემატა ხაზი `თავისუფალი → ფასიანი ჯავშანი | ...`
- **რა ქნა:** არაფერი.

## უარყოფა — `REJECTED_*`

ეს ნიშნავს: **მოთხოვნა მივიდა, გავიგე, მაგრამ განზრახ არ შევასრულე.**
ორივე შემთხვევაში ისტორიაში ჩანაწერი მაინც ჩაიწერება — ანუ კვალი რჩება.

### `REJECTED_SAME`
ბინას **უკვე აქვს** ის სტატუსი, რომელსაც ვგზავნით, და ეს სტატუსი **დაცულია**
(`ფასიანი ჯავშანი` ან `გაყიდული`).

- **მაგალითი:** Next-ში ბინა უკვე დარეზერვებულია, Archi კი ისევ რეზერვს აგზავნის.
- **Next-ში:** სტატუსს ხელი **არ ეხება**. ისტორიაში: `უკვე ფასიანი ჯავშანი — არ გადაიწერა`.
- **რა ქნა:** სავარაუდოდ ორმაგი რეზერვაციაა — ღირს მენეჯერის გაფრთხილება.

### `REJECTED_FOREIGN`
ბინას **Next-ში** აქვს დაცული სტატუსი (`ფასიანი ჯავშანი` ან `გაყიდული`) და ის **Archi-ს არ დაუყენებია**.

- **მაგალითი:** Next-ის ოპერატორმა ბინა თავად გაყიდა; Archi ცდილობს გაათავისუფლოს.
- **სიმეტრიულია:** იგივე ხდება პირიქითაც — Archi-ს ჯავშანს Next ვერ შეეხება (`$RESPECT_ARCHI = true`).
- **სამივე დაცული სტატუსი:** `უფასო ჯავშანი` · `ფასიანი ჯავშანი` · `გაყიდული`.
- **Next-ში:** სტატუსს ხელი **არ ეხება**. ისტორიაში: `თავისუფალი უარყოფილია — Next-ის გაყიდული`.
- **რა ქნა:** გადაამოწმე Next-თან. თუ Archi მართალია, სტატუსი ხელით გაასწორე Next-ში.

> **როგორ ვიგებთ, ვისია სტატუსი** — ისტორიიდან. ყოველ ჩვენს რეალურ ცვლილებას ხელს ვაწერთ
> `| Archi BP`-ით. კოდი პოულობს ბოლო ასეთ `X → Y` ხაზს: თუ `Y` ემთხვევა ახლანდელ სტატუსს,
> სტატუსი ჩვენია. თუ არა — Next-ში ხელით შეიცვალა, რადგან ხელით ცვლილებისას ისტორიაში
> არაფერი იწერება. სწორედ ეს სიჩუმეა Next-ის ხელმოწერა.

> ⚠️ თუ `Interga_History` გასუფთავდა, ბინა „Next-ისა" ხდება და Archi დაიბლოკება.
> ეს განზრახ ასეა — ეჭვის შემთხვევაში ჯობს არ გადააწეროს.

### `REJECTED_UNSAFE`
**ყველაზე მნიშვნელოვანი კოდი.** ნიშნავს: რაღაც არ ჯდება, ამიტომ **არაფერს არ ვეხები.**

ოთხი მიზეზი:

| მიზეზი | რას ნიშნავს |
|---|---|
| `PRODUCT_ID არასწორია` | გარიგების პოზიციაში ID ცარიელი ან ნულია |
| `ფილტრმა N პროდუქტი დააბრუნა` | ძებნამ ერთზე მეტი დააბრუნა — ფილტრი არ იმუშავა |
| `დაბრუნდა სხვა ბინა` | ნაპოვნი პროდუქტის ID არ ემთხვევა მოთხოვნილს |
| `ბინის ნომერი არ ემთხვევა` | Archi-სა და Next-ის ნომრები სხვადასხვაა |

- **Next-ში:** არაფერი. **Archi-ში:** არაფერი. ისტორიაშიც არაფერი.
- **რა ქნა:** ეს მონაცემების პრობლემაა. `Send_log`-ში ზუსტი მიზეზი წერია.

> ეს კოდი არსებობს იმიტომ, რომ ბიტრიქსი **ცარიელ ფილტრს უგულებელყოფს და მთელ კატალოგს
> აბრუნებს** — გატესტილია: `filter[ID] = ""` Archi-ზე 65 760 პროდუქტს აბრუნებს.
> ეჭვის შემთხვევაში ჯობს პროცესი გაჩერდეს, ვიდრე არასწორ ბინას შეეხოს.

### `REJECTED_MULTI`
გარიგებაზე **ერთზე მეტი ბინაა** მიმაგრებული.

- **Next-ში:** **არაფერი.** კოდი REST-ის გამოძახებამდე ჩერდება.
- **`Send_log`-ში:** ყველა ბინა ჩამოიწერება, რომ დაინახო რომლები იყო.
- **რა ქნა:** გარიგებაში ერთი ბინა დატოვე და ხელახლა გაუშვი.

## ნეიტრალური

### `UNCHANGED`
ბინას უკვე აქვს ეს სტატუსი, მაგრამ **დაცული არ არის** (`თავისუფალი`).

- **Next-ში:** სტატუსს ხელი არ ეხება — უაზრო ჩაწერა არ ხდება. ისტორიაში: `თავისუფალი (უცვლელი)`.
- **რა ქნა:** არაფერი. ეს ნორმაა.

> **`REJECTED_SAME` vs `UNCHANGED`** — ორივეში სტატუსი უცვლელია, მაგრამ:
> `REJECTED_SAME` = კონფლიქტი, ვცადე და დაცვამ არ გამატარა.
> `UNCHANGED` = ისედაც ასე იყო, საქმე არ იყო.

## მონაცემების პრობლემა

### `NO_DEAL`
გარიგების ID ვერ დადგინდა. `Send_log`-ში `docId`-ის სრული სტრუქტურა ჩაიწერება.
პრაქტიკულად ნიშნავს, რომ BP არასწორ კონტექსტში გაეშვა.

### `NO_PRODUCT`
გარიგებას **არცერთი ბინა არ აქვს** მიმაგრებული (ან `PRODUCT_ID` ცარიელია).
**რა ქნა:** მიამაგრე ბინა და ხელახლა გაუშვი.

### `NOT_FOUND`
ბინა გარიგებაზეა, მაგრამ **Next-ში არ არსებობს** ასეთი `PROPERTY_546`-ით.

- **ყველაზე ხშირი მიზეზი:** ეს ბინა „Not In Sale" იყო და იმპორტში არ მოხვდა (550 ასეთია).
- **რა ქნა:** ან ბინა Next-ში ატვირთე, ან გარიგებაში სხვა ბინა მიამაგრე.

### `BAD_STATUS`
BP ცვლად `status`-ში არასწორი ან ცარიელი მნიშვნელობაა.
მისაღებია: `free` · `reserved` · `sold` (ან ქართული ტექსტი ზუსტად).
**რა ქნა:** შეამოწმე „ცვლადის შეცვლის" ბლოკი BP-ში.

## ტექნიკური შეცდომა — `ERROR_*`

### `ERROR_AUTH`
webhook-ის ტოკენი არასწორია ან გაუქმდა. HTTP 401, `INVALID_CREDENTIALS`.
**რა ქნა:** Next-ზე ახალი webhook შექმენი და ტოკენი BP-ს კოდში ჩაასწორე.

### `ERROR_REST`
ბიტრიქსმა სხვა შეცდომა დააბრუნა — უფლებები, ველის პრობლემა, არასწორი პარამეტრი.
`Send_log`-ში ზუსტი ტექსტი წერია.

### `ERROR_NETWORK`
Next მიუწვდომელია, `curl` ჩავარდა ან timeout-ი ამოიწურა (20 წამი).
**რა ქნა:** ეს დროებითია. **retry არ არის** — სტატუსი ხელით უნდა გაასწორო.

## BP-ში პირობის დადება

```
თუ Logstat = UPDATED              -> არაფერი
თუ Logstat იწყება REJECTED_-ით    -> შეატყობინე მენეჯერს (კონფლიქტი)
თუ Logstat იწყება ERROR_-ით       -> შეატყობინე ადმინს (ტექნიკური)
დანარჩენი                          -> შეატყობინე მენეჯერს (მონაცემები)
```

ეს ჯერ **არ არის აწყობილი** — იხ. `docs/PLAN.md`, Milestone 2.
